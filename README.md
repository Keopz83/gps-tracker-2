# Summit

Summit is an Android app that records your route, distance, time and speed while jogging or riding a bicycle.

## Essential requirements

| ID    | Requirement |
|-------|-------------|
| REQ-1 | **Activity type & session control** — While no session is active, the front view shows only a runner and, below it, a bicycle icon button in its centre (besides the tone icon, REQ-14, and the *Export GPX* button after a stop, REQ-8); tapping one starts a *Jogging* or *Cycling* session. The time, distance, pace, kilometre paces and the session controls are only shown once a session is started. The session controls are round icon buttons, *Pause* (*Resume* while paused) and *Stop*, shown on the front view and on the map (REQ-17). Invalid transitions (e.g. pausing a session that has not started) are rejected. |
| REQ-2 | **GPS recording** — While a session is running the app records GPS positions. Positions received while idle, paused or stopped are ignored. To keep the track clean, a position is discarded when its accuracy is worse than 20 m, when it is less than 3 m from the previous recorded position (jitter), or when reaching it would require an implausible speed for the activity (jogging > 12 m/s, cycling > 30 m/s). |
| REQ-3 | **Distance** — The total distance is the sum of the great-circle (haversine) distances between consecutive recorded positions. The gap between the position before a pause and the first position after resuming is not counted. |
| REQ-4 | **Elapsed time** — The session shows the active time, excluding time spent paused, formatted as `MM:SS` (or `H:MM:SS` from one hour). |
| REQ-5 | **Speed / pace** — The session shows the average speed over the active time: pace in `min:ss /km` for jogging, `km/h` for cycling. Distance is shown in km with two decimals. |
| REQ-6 | **Background tracking & permissions** — Tracking keeps running with the screen off through a foreground service with a persistent notification. Before starting, the app requests precise location permission (plus notification permission on Android 13+); tracking only starts when location permission is granted. |
| REQ-7 | **Route map** — The map view (map icon, REQ-16) shows a map (OpenStreetMap data, served free by OpenFreeMap and drawn with MapLibre) with a recorded path, its last position marked and the gap between pausing and resuming not drawn. While a session is running or paused, the map shows that session once a position has been recorded: the path taken so far, which keeps growing while the map is open. When no session is active, it shows a finished run instead (REQ-17). |
| REQ-8 | **Run export (GPX)** — When a session is stopped, the run is saved as a GPX 1.1 file (one `<trkseg>` per segment between pauses, UTC timestamps, activity type `running`/`cycling`) so it can be imported into other sports apps such as Strava, Garmin Connect or Komoot. Runs without recorded positions are not saved. An *Export GPX* button shares the saved file through the Android share sheet. |
| REQ-9 | **Run history** — Every stopped run with recorded positions is added to a history that survives app restarts. The history view (history icon, REQ-16) lists the runs, newest on top, one line per run showing, from left to right: its order number (the oldest run is 1, so the newest has the highest number), the activity type icon, its start date and time (local, `yyyy-MM-dd HH:mm`), the name of the place where it started (town, else district, region or country), its distance (REQ-5) and its active duration (REQ-4); the distance and duration share one slightly highlighted background and are shown in a larger, bold font. Each run is a box with rounded corners. Below its line, the run's average pace or speed (REQ-5), e.g. *Average: 5:12 /km*, sits at the left and, at the right, a map icon that shows it on the map (REQ-17), a share icon (REQ-22) and a delete icon that removes the run (REQ-18). The place name is looked up with the phone's geocoder, which needs an internet connection; runs that cannot be named yet (offline, or recorded before place names were stored — their start is then read from their GPX file) are named the next time the app starts or a run is stopped. A tap on a run opens or closes its details in the list (REQ-22). |
| REQ-10 | **Look & icon** — Every screen has a diagonal gradient background running from red (top left) through purple to blue (bottom right), with white text and controls. The launcher icon uses the same gradient as its background with a white, abstract Matterhorn-like mountain in front. A small copy of the launcher icon, with the name *Summit* to its right, sits at the left of a bar across the top of every view (over the map too), like the bar of icons at the bottom (REQ-16). |
| REQ-11 | **Battery efficiency** — GPS tracking accuracy comes first: while running, the GPS reports a position every second at the highest accuracy, with the screen on or off, and no position is dropped to save power. Within that limit, battery use is kept low: with the screen off, positions are collected by the GPS chip and delivered in batches (at most 30 s late, Android 12+) so the phone can sleep in between, and are delivered at once when the screen turns on; while paused, the GPS stays on for 1 minute (so a short stop resumes without waiting for a fix) and is then switched off until resuming; the notification lets the system count the elapsed time and is only refreshed when the distance or state changes; the elapsed time on screen is refreshed every second only while the screen is on. |
| REQ-12 | **Kilometre pace** — The front view shows the pace of the last completed kilometre and of the three kilometres before it (newest first, in `min:ss /km`), or `--:-- /km` before the first kilometre. A kilometre's time is measured between recorded positions (the moment it is completed is interpolated between the positions either side of it), so time and distance spent paused are not counted. |
| REQ-13 | **Settings** — The burger icon at the bottom right opens a settings view, the last view when swiping right (REQ-16), with short labels and no descriptions, grouped in boxes like the runs in the history (REQ-9), each under a less see-through header: *Voice* holds *Note every km* (REQ-14), *Note every minute* (REQ-20), *Report on power button* (REQ-25), *Pause music* (REQ-14) and *Speaker* (REQ-21); *GPS* holds *Long distance* (REQ-26); *Cycling* holds *Rider* and *Bike*, their weights (REQ-28). The view scrolls when it does not fit. Settings are kept across app restarts. |
| REQ-14 | **Kilometre voice note** — An option, off by default, turned on and off either in the settings or with the tone icon at the top right of the front view (a speaker, crossed out while off), speaks a note each time a kilometre is completed with the total distance, the total active time and the last kilometre's pace in minutes and seconds per kilometre, or its speed in kilometres per hour (one decimal, as in the history, REQ-9) when cycling (e.g. *"3 kilometres. Time 16 minutes 5 seconds. Last kilometre 5 minutes 12 seconds per kilometre."* or *"… Last kilometre 24.0 kilometres per hour."*). While a note plays, other audio such as music is paused and resumes afterwards; with the *Pause music* setting turned off (it is on by default) it is only lowered instead (how far is decided by Android, which does not let an app lower it further). Notes that fall together are spoken one after the other. With this option or the minute note (REQ-20) on and the screen off, positions are batched for at most 5 s instead of 30 s (REQ-11) so the note comes on time. |
| REQ-15 | **Power saving warning** — Power saving can switch the GPS off while the screen is off (e.g. Samsung), which leaves gaps in the track that are drawn and counted as straight lines. When *Start* is pressed while power saving is on and limits location (or, before Android 9, whenever it is on), a note asks the user to turn power saving off, with *Open settings* (the power saving settings) or *Start anyway*. |
| REQ-16 | **Navigation** — A bar at the bottom of every view holds, in its middle, the record button (REQ-24) and, at its right, the icons of the map, the history and, at the very right, the settings burger icon; the icon of the open view is highlighted. The front view has no icon. The views are swiped through in the order front view, map, history, settings, rotating: swiping right from the front view shows the map, then the history, then the settings, and the next swipe right returns to the front view; swiping left goes round the other way (from the front view to the settings). Picking an icon goes to its view the shortest way round. *Back* returns to the front view. On the map, a one-finger swipe also moves between the views; the map itself is panned and rotated with two fingers (REQ-19). |
| REQ-17 | **Run on the map** — Tapping the map icon of a run in the history (REQ-9) selects it, highlights it in the list and moves to the map view. When no session is running or paused, the map shows the selected run, read from its saved GPX file (REQ-8), or the newest run when none is selected; starting a new session clears the selection. At the bottom of the map, over it, the shown run is summarised in a card with rounded corners that floats apart from the bar of icons below it and has the same colour as that bar. Everything laid over the map is see-through, so the map shows behind it: this card very slightly (90 % opaque), the bar of icons (the map runs on beneath it) and the bar of the app icon and name (REQ-10) more (70 % opaque). The map's logo and credits sit at its top right, clear of the card. It holds one line with the same information in the same order as in the history, without the order number and the icons below it: activity type icon, start date and time, place, distance and duration (for an active session the distance and duration so far, without a place). While the map shows an active session, the card also holds the session controls (REQ-1) below that line, so the session can be paused, resumed and stopped from the map; they are shown even before the first position is recorded. |
| REQ-18 | **Delete a run** — The delete icon at the right of a run in the history (REQ-9) asks for confirmation and then removes the run from the history and deletes its saved GPX file (REQ-8). The order numbers of the remaining runs are renumbered. If the deleted run was shown on the map, the map shows the newest run instead (REQ-17). |
| REQ-19 | **Map gestures** — On the map a one-finger drag does not move the map: it swipes to the next or previous view (REQ-16), following the finger, and moves on when it is dragged past half the screen or flicked. Panning and rotating the map need two fingers; pinching zooms. A one-finger tap still reaches the map (e.g. a double tap zooms in, the compass turns the map back to north). Tilting is off, so a two-finger drag up or down pans the map. |
| REQ-20 | **Minute voice note** — An option in the settings, off by default, speaks a note each time another whole minute of active time (REQ-4) is reached, with the time, the total distance in kilometres (two decimals) and the average pace so far in minutes and seconds per kilometre, or the average speed in kilometres per hour when cycling (*"Average speed 19.2 kilometres per hour."*) (left out before any distance is covered), e.g. *"5 minutes. Distance 0.84 kilometres. Average pace 5 minutes 57 seconds per kilometre."* It is spoken like the kilometre note (REQ-14), at most one position batch late. |
| REQ-21 | **Voice** — The settings offer a *Female* (default) or *Male* voice for the notes. Android does not tell a voice's gender, so it is recognised from the voice's name (Google and Samsung voices, and names containing "female" or "male"); an installed British English voice of that gender is used first, then an American one, then any English one, preferring voices that work offline. When the phone's default text-to-speech engine has no such voice (e.g. Samsung's only ships female English voices), the other installed engines, such as Google's, are tried; when none has one, the default voice is used. |
| REQ-22 | **Share and details of runs** — The share icon of a run in the history (REQ-9) shares its saved GPX file (REQ-8) through the Android share sheet. A long press on a run selects it (marked with a check in place of its order number and a white border); while any run is selected, a tap selects or unselects a run instead of opening its details. The share icon at the top right of the history view, dimmed while nothing is selected, shares the GPX files of all selected runs at once, next to their count and an icon that clears the selection. A tap on a run (while none is selected) opens its details below its line, and a second tap closes them; while they are open, the run's line and icons above them form a less see-through header, and the details keep the box's usual see-through background: read from its GPX file, its pace chart (speed when cycling), the estimated power chart when cycling (REQ-28) and elevation chart (REQ-23) and below them the time and pace (speed when cycling) of each completed kilometre (REQ-12). |
| REQ-23 | **Run charts** — The details of a run (REQ-22) start with a bar chart of its pace in `min:ss /km` (y axis) against active time (x axis, pauses left out): one bar per minute of active time (longer runs use bars of several whole minutes, so there are at most 40), with no bar for a stretch of less than 10 m and none for the last, unfinished stretch. The y axis is inverted so faster stretches get taller bars: the fastest pace (rounded down to a whole minute) is at the top and one minute more than the slowest pace (rounded up) at the bottom, so every bar shows; the slowest pace counts as at most twice the median pace, so a few slow stretches (e.g. waiting at a crossing) are cut off rather than flattening the other bars. For a cycling run the chart shows speed in km/h instead, with the same bars: the y axis runs from 0 km/h at the bottom to the fastest speed rounded up to 5 km/h at the top, with a grid line every 5 km/h (every 10 above 40 km/h). Below it, after a see-through horizontal line, an elevation chart shows the altitude against the same active time, between its lowest and highest point (at least 10 m apart). At its top right it shows the total metres climbed and descended, each after a diagonal arrow up or down (e.g. *↗ 124 m ↘ 118 m*); GPS altitude jitters by a few metres, so a rise or fall only counts once the altitude has moved at least 5 m from the last counted point. Another such line separates it from the kilometre list. The time axis of both charts is labelled at round minutes, about 5 labels: every 1, 2, 5, 10, 15, 20 or 30 minutes or 1, 2, 3, 4 or 6 hours, the smallest step giving at most 6 labels (e.g. every minute for 6 minutes, every 5 minutes for 26 and every 10 minutes for 52). The altitude of each position is recorded (above sea level on Android 14+ when the phone knows it, else the GPS height) and saved as `<ele>` in the GPX file (REQ-8); runs recorded before that show *No elevation data*. |
| REQ-24 | **Record button** — In the middle of the bottom bar (REQ-16), on every view but the front view (which has its own start buttons and session controls, REQ-1; the button fades out there and its place stays empty), a round button larger than the icons beside it controls the session in one place: while no session is active it shows a record icon, and pressing it shows the runner and bicycle buttons of the front view (REQ-1), smaller, stacked above it with the runner on top, sliding up out of it (and back down when closed) (each starts its session like on the front view, REQ-15, and moves to the front view; a tap elsewhere closes them); while a session is running it shows *Pause*, and while paused *Resume* (a play icon). Stopping stays on the front view and the map (REQ-1, REQ-17). |
| REQ-25 | **Screen-on report** — An option in the settings, off by default, speaks a report each time the screen is turned on while a session is running or paused — with the app in the background and the screen off, one press of the power button is enough. Android does not let an app catch the power button itself, so the report follows the screen turning on, whatever turned it on (e.g. a notification that lights up the screen). The report gives the active time (REQ-4), the total distance in kilometres (two decimals) and the average pace so far in minutes and seconds per kilometre, or the average speed in kilometres per hour when cycling (*"Average speed 19.2 kilometres per hour."*) (left out before any distance is covered), e.g. *"Time 16 minutes 5 seconds. Distance 3.02 kilometres. Average pace 5 minutes 20 seconds per kilometre."* It waits for the positions batched while the screen was off (REQ-11) so the distance is up to date, and is spoken like the kilometre note (REQ-14). |
| REQ-26 | **Long distance** — An option in the settings, off by default, makes the GPS report a position less often than every second (REQ-11) to save battery on long activities: every 5, 10 (default), 30 or 60 s, picked below the option while it is on. It also applies during the first minute of a pause and takes effect at once, also during a session. |
| REQ-27 | **Saved while running** — While a session is running or paused, it is written to file every 10 s whenever new positions were recorded (positions batched while the screen is off, REQ-11, are written once delivered). When the app is closed or crashes during a session, the next time it starts the session is added to the history (REQ-9) as it was last written, with its GPX file (REQ-8). |
| REQ-28 | **Cycling power** — The details of a cycling run (REQ-22) show, between the speed chart and the elevation chart (REQ-23) and separated from both by the same see-through line, a bar chart *Power (W, estimated)* with the same bars and time axis as the speed chart. No power meter is read: each bar's power is estimated from its average speed and its change of altitude, as the power to overcome rolling resistance (Crr 0.005), air drag in still air (CdA 0.32 m², air density 1.225 kg/m³) and climbing, divided by a drivetrain efficiency of 97.6 %; a bar needing less than nothing (coasting downhill) shows 0 W, and a run without altitudes is estimated as flat. The y axis runs from 0 W at the bottom to the highest power rounded up to 100 W at the top, with a grid line every 100 W (every 200 W above 600 W). The weight it is estimated for is the rider's plus the bike's, entered as whole kilograms in the *Cycling* settings (REQ-13): *Rider* (30–200 kg, 75 kg by default) and *Bike* (3–40 kg, 10 kg by default); a value outside the range is marked as wrong and not kept. The current weights are used for every cycling run, also those recorded earlier. |

## Project layout

- `app/src/main/java/com/example/gpstracker/domain` — platform-independent tracking logic (session, filtering, distance, formatting, permissions).
- `app/src/main/java/com/example/gpstracker` — Android layer: `TrackingService` (foreground location service), `TrackingRepository` (shared state) and `MainActivity` (Compose UI).
- `app/src/test` — JVM unit tests; each test name starts with the requirement it covers (e.g. `REQ-3 ...`).

## Build & test

Requires JDK 17 and the Android SDK (platform 35).

```sh
./gradlew testDebugUnitTest   # run the requirement tests
./gradlew assembleDebug       # build the APK
```

If `java` is not on your path, point Gradle at a JDK 17 first, e.g. `export JAVA_HOME=/opt/homebrew/opt/openjdk@17` (Homebrew `openjdk@17`). The SDK location is read from `local.properties` (`sdk.dir=...`), which is not committed.

## Deploy to a phone

1. **Enable developer mode** — tap *Build number* seven times (Samsung: *Settings › About phone › Software information*; Pixel: *Settings › About phone*).
2. **Connect the phone** with `adb` (in `<sdk>/platform-tools`), either:
   - **USB** — enable *Developer options › USB debugging*, plug in the cable and accept the prompt on the phone; or
   - **Wi‑Fi** (Android 11+, phone and computer on the same network) — enable *Developer options › Wireless debugging*, tap *Pair device with pairing code*, then:
     ```sh
     adb pair <ip>:<pairing-port>     # enter the pairing code shown on the phone
     adb connect <ip>:<port>          # the IP address & port shown on the Wireless debugging screen
     ```
3. **Check** the phone is listed as `device` (not `unauthorized`):
   ```sh
   adb devices -l
   ```
4. **Build, install and launch** (`-r` replaces an existing install and keeps its data):
   ```sh
   ./gradlew assembleDebug
   adb install -r app/build/outputs/apk/debug/app-debug.apk
   adb shell am start -n com.example.gpstracker/.MainActivity
   ```
   `./gradlew installDebug` builds and installs in one step. With several devices connected, add `-s <serial>` to the `adb` commands (or set `ANDROID_SERIAL`).

Reinstalling stops a running tracking session. On first start, grant precise location (and notifications) when asked. The route map needs an internet connection for its map tiles.
